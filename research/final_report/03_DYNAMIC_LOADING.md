## 2. JNA (Java Native Access)

### 2.1 Подтверждение

**Библиотека:** libjnidispatch.so (157,720 bytes)  
**Расположение:** apk_contents/lib/arm64-v8a/

### 2.2 Функциональность

JNA позволяет:
1. Загружать native-библиотеки по пути
2. Находить функции по имени (без JNI-заголовков)
3. Вызывать функции с произвольной сигнатурой
4. Работать с указателями и структурами

### 2.3 Использование в приложении

```java
// Предполагаемый сценарий:
// 1. Загрузка libche.so или libmodulese.so через JNA
// 2. Поиск функции по имени (имя может быть обфусцировано)
// 3. Вызов функции с параметрами
```

**Значение:**
- Обходит статический анализ (нет явных JNI-вызовов)
- Позволяет динамическое разрешение символов
- Имена функций могут храниться в зашифрованных строках

## 3. ONNX Runtime

### 3.1 Подтверждение использования

**Файл:** MyCarReceiver.java  
**Код:**
```java
// MyCarReceiver.s() метод:
StringBuilder sbU = ai.onnxruntime.a.u(str);
sbU.append(m.h(new byte[]{-6, -17, -73, 17, -73}, new byte[]{-91, -69, -14, 92, -25, -10, -12, -43}));
sbU.append(f786o);
int iLoadInt2 = aVarO.loadInt(sbU.toString(), 40);
```

### 3.2 Анализ

- `ai.onnxruntime.a.u(str)` — хэширование ключа для модели
- Параметры загружаются из SharedPreferences
- Модель используется для инференса (предсказания)
- Результат влияет на управление параметрами автомобиля

### 3.3 Загрузка модели

**Возможные источники:**
1. assets/ — предустановленная модель
2. Сеть — загрузка через OkHttp3
3. Генерация — динамическое создание модели

**Библиотеки:**
- libonnxruntime.so (30.6 MB) — C++ runtime
- libonnxruntime4j_jni.so (81 KB) — JNI bridge

## 4. Поиск DexClassLoader и аналогов

### 4.1 Результаты поиска в jadx_full

**Не обнаружено:**
- DexClassLoader
- PathClassLoader (явное создание)
- InMemoryDexClassLoader
- BaseDexClassLoader (явное создание)

### 4.2 Возможные причины отсутствия

1. **Код в smali_dex1/smali_dex2** — может быть в обфусцированном виде
2. **Рефлексия** — Class.forName() с обфусцированными именами
3. **JNA** — загрузка через native-код
4. **Отсутствие** — динамическая загрузка не используется

### 4.3 Рекомендации

Для полного подтверждения необходимо:
- Проанализировать smali_dex1 на наличие DexClassLoader
- Проанализировать smali_dex2 полностью
- Поискать Class.forName() в smali
- Проверить assets/ на наличие .dex/.jar/.apk файлов

## 6. Обфусцированная загрузка классов

### 6.1 Обфусцированные пакеты

smali_dex1 содержит ~200+ пакетов:
- a, b, c... z (однобуквенные)
- a0, a1... a8, b0, b1... z8 (с числовыми суффиксами)
- ai/ (ONNX), alfusos/ (специальные)

### 6.2 Динамическое формирование имён

```java
// Пример из кода:
String className = m.h(encrypted_bytes, key_bytes);
Class<?> clazz = Class.forName(className);
```

**Проблема:**
- Без деобфускатора m.h() невозможно установить реальные имена
- XOR-шифрование требует знания ключа

## 7. Загрузка через JNI

### 7.1 Гипотеза

libche.so или libmodulese.so могут:
1. Загружать DEX из файла
2. Создавать ClassLoader
3. Загружать классы динамически
4. Вызывать методы через JNI

### 7.2 Подтверждение

**Статус:** НЕ ПОДТВЕРЖДЕНО  
**Требуется:** Бинарный анализ ELF
