# 09 — UNRESOLVED QUESTIONS
## Нерешённые вопросы и ограничения

---

## 1. Вопросы высокого приоритета

### 1.1 Полная JNI-регистрация libche.so

**Статус:** НЕ ПОДТВЕРЖДЕНО  
**Проблема:** Без бинарного анализа ELF невозможно подтвердить:
- Наличие JNI_OnLoad
- Таблицы RegisterNatives
- Точные JNI-сигнатуры
- Адреса функций
- Все экспортируемые символы

**Требуется:** readelf, nm, objdump, Ghidra/IDA  
**Влияние:** Невозможно восстановить полную картину JNI-вызовов

---

### 1.2 Содержимое smali_dex2

**Статус:** НЕ ПОЛНОСТЬЮ ПРОАНАЛИЗИРОВАН  
**Проблема:** Каталог smali_dex2 существует, но:
- Не построен полный индекс
- Не проверено наличие carsC.P
- Не найдены все динамические загрузчики

**Требуется:** Полный grep по smali_dex2/  
**Влияние:** Возможно упущены критические классы

---

### 1.3 URL серверов обновления

**Статус:** НЕ УСТАНОВЛЕНЫ  
**Проблема:** Все строки обфусцированы через `m.h(byte[], byte[])`:
- URL серверов
- Имена параметров
- Ключи API

**Требуется:** Реализация деобфускатора m.h()  
**Влияние:** Невозможно установить реальные серверы и протоколы

---

## 2. Вопросы среднего приоритета

### 2.1 Класс com.example.navistart.carsC.P

**Статус:** НЕ НАЙДЕН  
**Проблема:** Класс отсутствует во всех статических представлениях:
- Не найден в jadx_full
- Не найден в smali_dex1
- Не проверен полностью smali_dex2

**Гипотезы:**
- Динамическая генерация
- Обфускация имени
- Нахождение в smali_dex2

**Требуется:** Полный анализ smali_dex2, динамический анализ  
**Влияние:** Невозможно установить функциональность класса

---

### 2.2 DexClassLoader и динамическая загрузка DEX

**Статус:** НЕ ОБНАРУЖЕНО в jadx_full  
**Проблема:** В Java-декомпиляции не найдены:
- DexClassLoader
- PathClassLoader (явное создание)
- InMemoryDexClassLoader

**Возможные причины:**
- Находятся в обфусцированном smali
- Используются через рефлексию
- Загрузка через JNI

**Требуется:** Поиск в smali_dex1 и smali_dex2  
**Влияние:** Возможно упущен механизм динамической загрузки кода

---

### 2.3 Содержимое assets/

**Статус:** НЕ ПРОИНВЕНТАРИЗОВАНО  
**Проблема:** Каталог assets/ присутствует, но содержимое неизвестно:
- Модели ONNX?
- Модели Vosk?
- Конфигурации?
- DEX файлы?

**Требуется:** Инвентаризация assets/  
**Влияние:** Невозможно установить источники данных

---

### 2.4 Дополнительные native-методы

**Статус:** ВОЗМОЖНЫ  
**Проблема:** Обнаружены вызовы, но библиотека не подтверждена:
- b.c().StartProGu()
- b.d().c(JSONObject)
- b.d().bezoff(BezFunEnum)
- b.d().hybrid(HFunEnum)

**Требуется:** Бинарный анализ libmodulese.so  
**Влияние:** Неполная картина JNI-вызовов

---

## 3. Вопросы низкого приоритета

### 3.1 Полный список обфусцированных строк

**Статус:** НЕ ДЕОБФУСЦИРОВАНЫ  
**Проблема:** m.h(byte[], byte[]) используется повсеместно:
- Имена actions
- Ключи SharedPreferences
- URLs
- Имена классов

**Требуется:** Реализация XOR-дешифратора  
**Влияние:** Невозможно прочитать зашифрованные строки

---

### 3.2 libmodulese.so — точная функциональность

**Статус:** ГИПОТЕЗА  
**Проблема:** Без бинарного анализа невозможно установить:
- Экспортируемые символы
- Вызовы JNI API
- Связи с Java-классами
- Реализацию функций

**Требуется:** readelf, nm, objdump  
**Влияние:** Неполное понимание модулей

---

### 3.3 WorkManager / JobScheduler / AlarmManager

**Статус:** НЕ ОБНАРУЖЕНЫ  
**Проблема:** В jadx_full не найдены явные использования

**Возможные причины:**
- Используются через обфусцированные классы
- Заменяются на ScheduledThreadPoolExecutor
- Отсутствуют

**Требуется:** Поиск в smali  
**Влияние:** Неполная картина фоновых задач

---

### 3.4 VPN Service

**Статус:** ВЕРОЯТНО, НЕ ПОДТВЕРЖДЕНО  
**Проблема:** WireGuard библиотеки присутствуют, но:
- VpnService не найден в jadx_full
- Конфигурация VPN не обнаружена

**Требуется:** Поиск VpnService в smali  
**Влияние:** Непонятен механизм VPN

---

## 4. Ограничения исследования

### 4.1 Инструментальные ограничения

| Ограничение | Влияние |
|---|---|
| Нет бинарного анализа ELF | Невозможно анализировать .so файлы |
| Нет Ghidra/IDA | Невозможен реверс-инжиниринг native кода |
| Нет динамического анализа | Невозможно наблюдать runtime поведение |
| Нет доступа к устройству | Невозможно запустить приложение |

### 4.2 Ограничения данных

| Ограничение | Влияние |
|---|---|
| smali_dex2 не проиндексирован | Возможно упущены классы |
| assets/ не проанализирован | Неизвестны источники данных |
| Строки обфусцированы | Невозможно прочитать URLs, имена |
| JADX декомпиляция неполная | Некоторые методы не восстановлены |

### 4.3 Временные ограничения

- Исследование выполнено за один цикл
- Приоритет отдан наиболее критичным направлениям
- Некоторые направления требуют дополнительного времени

## 5. Рекомендации для дальнейшего исследования

### 5.1 Критические шаги

1. **Реализовать деобфускатор m.h()**
   - Извлечь XOR-ключи из кода
   - Деобфусцировать все строки
   - Найти URLs, имена классов, actions

2. **Полный анализ smali_dex2**
   - Индексировать все файлы
   - Поиск carsC.P
   - Поиск DexClassLoader

3. **Бинарный анализ ELF**
   - readelf -a libche.so
   - nm -D libche.so
   - objdump -d libche.so

### 5.2 Дополнительные шаги

4. **Инвентаризация assets/**
   - Список всех файлов
   - Определение типов
   - Анализ содержимого

5. **Поиск в smali_dex1**
   - grep "DexClassLoader"
   - grep "Class.forName"
   - grep "carsC"

6. **Динамический анализ**
   - Запуск на эмуляторе
   - Мониторинг ClassLoader
   - Перехват JNI-вызовов
